# Mini CRM

고객 문의를 등록하고 처리 상태를 관리하는 웹 앱입니다. 고객명과 제목으로 검색하고, 접수·처리 중·완료 상태별로 문의를 확인할 수 있습니다.

[배포된 Mini CRM 열기](https://mini-crm-pi-gold.vercel.app/)

## 주요 기능

- 이메일과 비밀번호로 로그인
- 문의 등록, 조회, 수정, 삭제 및 상태 변경
- 고객명·제목 검색과 처리 상태 필터
- 요청 중 표시, 조회 실패 후 재시도, 저장 및 삭제 결과 안내
- 모바일 대응 화면과 키보드로 조작 가능한 폼
- PostgreSQL에 문의 저장 및 계정별 행 접근 제어

## 기술 선택

React의 상태로 폼, 문의 목록, 검색과 필터를 관리합니다. Vite로 개발 서버와 배포용 빌드를 실행합니다. JavaScript `fetch`가 Supabase Auth와 PostgREST에 요청을 보내며 PostgreSQL이 입력 제약과 계정별 권한을 적용합니다.

`App.jsx`의 `useEffect`는 로그인 후 문의를 조회하고, 화면이 닫히면 대기 중인 조회를 취소합니다. 문의 카드에는 표시할 데이터와 이벤트 함수를 props로 전달합니다. 등록·수정·삭제 이벤트는 `async/await`로 서버 응답을 기다린 뒤 화면을 갱신합니다.

## 로컬 실행

Node.js 24 LTS와 npm이 필요합니다.

1. Supabase 프로젝트의 **SQL Editor**에서 [schema.sql](supabase/schema.sql)을 실행합니다.
2. **Authentication → Users**에서 이메일과 비밀번호로 사용자 계정을 만듭니다. 관리자만 계정을 만들게 하려면 Auth 설정에서 신규 가입을 비활성화합니다.
3. 프로젝트 루트에서 `.env.example`을 복사해 `.env.local`을 만들고 Supabase 프로젝트 URL과 `sb_publishable_` 공개 키를 입력합니다.
4. 다음 명령을 실행하고 터미널에 표시되는 주소에서 로그인합니다.

```bash
npm ci
npm run dev
```

로그인 세션은 현재 탭의 메모리에만 보관됩니다. 새로고침하거나 토큰이 만료되면 다시 로그인합니다. 문의는 DB에 남습니다.

## Vercel 배포

GitHub 저장소를 Vercel에서 가져오고 **Vite** 프리셋을 선택합니다. 빌드 명령은 `npm run build`, 출력 폴더는 `dist`입니다. 환경 변수에 `VITE_SUPABASE_URL`과 `VITE_SUPABASE_PUBLISHABLE_KEY`를 추가하고 배포합니다. `VITE_` 값은 브라우저에 포함되므로 `sb_secret_` 키나 서비스 역할 키를 여기에 넣으면 안 됩니다.

배포 URL에서 테스트 계정 두 개로 검증합니다. A 계정에서 문의를 만들고 재로그인 후 조회되며, B 계정에서는 해당 문의가 보이지 않아야 합니다. 로그인 없이 데이터 API에 접근할 수 없는지도 확인합니다. 포트폴리오 시연에는 가상 고객 데이터를 사용합니다.

## 개발 기록과 검증

- Day 1에는 가상 문의 목록과 `useState`로 상태 변경을 구현했습니다.
- 완성본에서는 화면 상태와 저장된 데이터를 구분하고, 서버 응답이 성공한 뒤 문의 목록을 바꾸도록 개선했습니다.
- 로컬의 `npm audit`에서 Vite의 간접 의존성인 `picomatch` 경고를 확인했습니다. 당시 `npm audit --omit=dev`에서는 0건이었으며 강제 버전 변경은 적용하지 않았습니다.
- 배포용 빌드와 모의 REST 응답을 사용한 Chromium 사용자 흐름을 확인했습니다.
- 로컬 PostgreSQL 엔진에서 계정별 조회·수정·삭제 차단과 익명 접근 거부를 검증했습니다.
- Vercel 운영 URL에서 로그인 화면이 열리고, 운영 Supabase가 익명 문의 조회 요청을 거부하는 것을 확인했습니다. 운영 계정으로 테스트 문의를 등록한 뒤 로그아웃하고 다시 로그인해, 저장된 문의가 목록에 표시되는 것을 확인했습니다.
